# 企業授信覆審 AI Agent PoC

本機可操作的 HTML 前端＋Python 財務分析與報告生成器。無 API 金鑰也能展示完整流程；可選擇接入本機 Ollama，排序可驗證的風險證據。所有範例與政策均為虛構示範，需人工覆核。

Vercel 雲端展示版已備妥 api/、public/ 與 vercel.json，操作見 DEPLOY_VERCEL.md。尚未發布至 Vercel；雲端上傳上限 3 MB，使用規則摘要。本機版仍維持 10 MB 與可選 Ollama。

## 啟動

Python 3.10 以上：

```sh
cd credit-review-poc
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python server.py
```

開啟 http://127.0.0.1:8765。按「載入示範案例」即可展示。CSV 基本流程僅用 Python 標準函式庫；Excel 與 PDF 需安裝 requirements。`PORT=8766 python server.py` 可更改埠號。服務僅綁定 127.0.0.1，不適合直接對外部署。

## 操作

1. 載入示範案例，或下載 CSV 範本，替換成企業財報數據。
2. 確認企業名稱、幣別、金額單位與報表範圍。資料必須為同範圍、相鄰兩個全年期間。
3. 執行分析，檢視訊號、公式及來源連結；缺漏、零分母與勾稽錯誤需先釐清。
4. 在人工比對區輸入當期人工計算值，按「更新比對」。百分比使用小數，如 70%=0.7。
5. 填寫覆核意見並下載 HTML 銀行風險報告。用瀏覽器列印可另存 PDF。

## 財報格式與解析範圍

CSV 與 Excel 首張工作表均採三欄 `metric,2024,2025`，年度可調整但須遞增且相鄰。支援英文科目與部分中文別名，完整科目見 engine.py 的 FIELDS／ALIASES。每個科目僅能出現一次；缺漏留白，負值可用括號。不要在數字後加幣別或單位。

文字型 PDF 需要 `metric 2024 2025` 或 `科目 2024 2025` 表頭，各列為「科目 前期金額 當期金額」，同一行三欄，以空白分隔。PDF 解析目前不支援任意版面、跨欄或財報註解推斷。掃描文件需先 OCR，再由人工確認數字。Excel 公式必須先在 Excel 儲存計算快取；無快取會視為缺漏，系統不執行公式、巨集或外部連結。

這是有限格式解析的 PoC，並非已能解析所有真實企業財報。先標準化可避免把附註數字或不同報表範圍誤作同一科目。Excel 金額來源記錄工作表、列欄；PDF 記錄頁碼與原文；CSV 記錄列欄。原檔 SHA-256 留在分析與報告供追溯。

## Agent 與 RAG

```
Parse → Validate → Calculate → Detect → Retrieve → Generate → Human review
```

Python 用 Pandas 讀 Excel，pypdf 讀 PDF；比率使用確定性公式。此 PoC 是有明確狀態與工具階段的工作流程 Agent，未引入 LangChain／AutoGen，以減少安裝負擔。RAG 使用風險 ID 查找內建示範政策段落，屬確定性檢索，未使用向量庫或 embedding，也不包含任意 PDF 語意問答。

預設為規則／模板摘要，介面不宣稱已使用 LLM。選用模型時，將檢索證據與已計算風險送入本機模型，再驗證回傳 ID，並以既有文字組裝摘要。模型只排序重要性，不能新增數字、政策或自由結論。報告下載重新從原始檔計算，使用規則摘要，保留使用者輸入的人工值及覆核意見。

本機已有 Ollama 與模型時：

```sh
OLLAMA_MODEL=你的已安裝模型名稱 python server.py
```

勾選前端「啟用本機 Ollama」。固定呼叫 `127.0.0.1:11434/api/chat`，逾時 45 秒；只傳風險與政策，不傳企業名稱或原始財報。模型未設定、無法連線、輸出不符或引用未驗證時，回退到規則摘要並顯示訊息。

## 財務方法

- 流動比率、速動比率、負債比率、利息保障、淨利率、ROA、ROE、營業現金流／流動負債。
- ROA 與 ROE 使用期初期末平均餘額；前期缺少更早一期資料，顯示無法計算。非正分母不計算，避免負權益產生誤導結果。
- 年增減以前期正值為基準；前期為零、負值或缺漏時不計算成長率。
- 預設異常：營收年減 ≥20%、負債年增 ≥30%、流動比率 <1、負債比率 >70%、利息保障 <2、營業現金流 <0。前五項可在介面調整。
- 目前為可解釋的規則式異常偵測，兩年資料不足以訓練統計異常模型，不宣稱使用 Isolation Forest 或預測違約機率。
- 人工數值比對容許誤差為相對 0.1% 或絕對 0.0001，取較大值；未提供值不計入一致率。
- 缺漏科目與不平衡財報會讓覆審結論要求補件。零分母不替換為 0；不製造信用分數。

## 避免幻覺與評估

數值由程式計算；每項風險關聯科目 ID、原始位置、觸發規則與政策 ID。模型不能寫自由事實，只能排列已存在 ID，且不得遺漏或重複。這降低自由生成造成的幻覺，但來源數字、科目映射、OCR 与人工輸入仍需覆核。

示範案例預期：營收年減 35%、負債比率 76.25%、流動比率 0.892857、利息保障 1.210526，共六項異常。此為合成資料驗證，未衡量真人分析時間或真實授信準確率。建議正式 POC 以去識別化財報、雙人覆核 ground truth 衡量科目抽取正確率、比率誤差、風險漏報率、無來源陳述率與覆審工時。不可把畫面一致率当作模型準確率。

## 驗證

```sh
python -m unittest discover -s tests -v
```

測試覆蓋範例比率、平均餘額、來源關聯、零分母／缺漏、不平衡、負權益、重複科目、不相鄰期間、無限值、人工差異、LLM 增刪／重複 ID 拒絕，以及報告 HTML 跳脫。PDF／Excel 科目映射測試使用 mock parser，另以真實文件做整合驗證後記錄於 VALIDATION.md。

## 上線前範圍

此本機版本無認證、權限管理、正式簽核、稽核資料庫、加密儲存、模型品質基準或銀行政策版控。請勿直接以未去識別化真實客戶資料對外部署。人員簽核欄是使用者文字，並非已驗證簽章。原始上傳內容僅在記憶體使用，報告由瀏覽器下載，不寫入伺服器資料庫。
